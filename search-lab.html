Concept · 01
Linear Search
What is it?

Linear search scans every element from the start until the target is found or the list is exhausted. It requires no sorting and no pre-processing. It is the simplest possible search strategy.

Real World: Finding a Name in an Unsorted Register

Imagine a paper registration list for a conference of 50,000 attendees written in the order people registered — not alphabetically. To find "Zaw Hein Htet" you must read every name from the top until you reach his. On average you read half the list (25,000 names). In the worst case you read all 50,000.

A social network with 1 billion users stored in insertion order would require up to 1 billion comparisons per login — roughly 4 seconds of CPU time per search at 250 million comparisons/second. At 1 million logins per second, that is 4 million CPU-seconds per second. Impossible.

Real World: Virus Scanner

An antivirus scanner checking every byte of a 4 GB drive against a signature list is performing linear search. With no index, it must inspect every byte. This is why full scans take hours — and why indexes and bloom filters are added to accelerate real scanners.

CaseComparisonsReal example (n = 1 billion)
BestO(1)Target is the first element

When to use it

Linear search is appropriate when the dataset is small (under ~1,000 elements), unsorted and sorting is too expensive, or the search happens only once. For any repeated search over large data, a sorted structure or hash map is always faster.

Concept · 02
Binary Search
What is it?

Binary search works on a sorted dataset. At each step it picks the middle element. If the target is smaller, it discards the right half. If larger, it discards the left half. Each comparison eliminates half the remaining candidates.

Real World: Dictionary Lookup

Nobody starts at page 1 of a dictionary to find "zebra." You open near the end, see "M," realise the target is to the right, open further right, see "U," narrow again. You find a 300,000-word dictionary in about 18 page-opens — log₂(300,000) ≈ 18.

Real World: Git bisect

Git's bisect command finds which commit introduced a bug using binary search over commit history. With 1 million commits, it finds the culprit in at most 20 tests — not 1 million. Every developer uses this without necessarily knowing the name of the algorithm.

Complexity
CaseComparisonsReal example (n = 1 billion)
BestO(1)Target is the midpoint

The cost: sorting

Binary search requires a sorted array. Sorting n elements costs O(n log n). This upfront cost is paid once; every subsequent search costs only O(log n). For any dataset searched more than once, the trade-off is always worth it.

Concept · 03
Hash Search
What is it?

Hash search converts the key directly to an array index using a hash function. Rather than scanning (linear) or narrowing (binary), it jumps to the exact slot in one step. Average case is O(1) — constant time regardless of dataset size.

Real World: Database Index

When you run SELECT * FROM users WHERE username = 'alice', a hash index on the username column converts 'alice' to a slot number and retrieves the row directly — no row-by-row scan. PostgreSQL, MySQL, and Redis all use hash indexes for exact-match lookups.

Real World: DNS Resolution

Your browser converts "google.com" to an IP address using a local DNS cache — a hash map of domain → IP. The lookup is instant regardless of how many domains are cached, because the domain name is hashed directly to a cache slot.

The three steps

Step 1 — Hash the key: convert the key string to a number by summing or combining char codes.

Step 2 — Division method: slot = hash(key) mod slotCount — clamp the hash to a valid array index.

Step 3 — Check the slot: if the slot contains the key, return the value. If empty, the key does not exist. If occupied by a different key, a collision occurred — probe the next slot.
