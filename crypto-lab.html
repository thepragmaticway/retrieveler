XOR Cipher
What is XOR?

XOR (exclusive OR) is a bitwise operation. Given two bits, it outputs 1 if the bits are different and 0 if they are the same. Think of it as "one or the other, but not both."

Truth Table
ABA XOR B
000
011
101
110
The Magic Property

XOR is its own inverse. If you XOR a value with a key, then XOR the result with the same key again, you get the original value back:

message XOR key = ciphertext

ciphertext XOR key = message

This means the same operation encrypts and decrypts. The key is both the lock and the key.

One-Time Pad Rule

For XOR encryption to be unbreakable, three rules must hold: the key must be truly random, at least as long as the message, and never reused. Breaking any rule leaks information about the message. This scheme is called a one-time pad.

One-Way Functions
Definition

A one-way function is easy to compute in one direction but computationally infeasible to reverse. Given x, computing f(x) is fast. Given f(x), finding x is practically impossible.

Real World: Diode (AC → DC)

A diode lets current flow in only one direction. Feed it alternating current (AC, which swings positive and negative) and it outputs direct current (DC, positive only). You cannot reconstruct the original AC wave from the DC output — information is permanently lost.

Real World: Mixing Paint

Mixing blue and yellow paint produces green. Given the green paint, you cannot separate it back into the original blue and yellow. The forward operation is trivial; the reverse is impossible.

🟡Yellow

Why This Matters in Crypto

If we can find a mathematical one-way function, we can store a transformed version of a password. The server can verify a login by applying the same function to the submitted password and comparing outputs — without ever needing to store or recover the original password.

Concept · 03
Modulo & Trapdoors
Modulo — the remainder

a mod n is the remainder after dividing a by n. It is like a clock: after reaching 12 it wraps back to 1. Knowing the current time tells you nothing about how many full rotations occurred.

Clock Analogy

14:00 on a 12-hour clock shows 2. But 2 could have come from hour 2, 14, 26, 38... You know the remainder, not the original value. This is the same ambiguity that makes modulo useful in cryptography.

Why Exponentials Grow So Fast

Imagine folding a piece of paper in half repeatedly. Each fold doubles the thickness. After 10 folds it is about as thick as a hand. After 30 folds it is taller than Mount Everest. After 42 folds it reaches the Moon. The thickness grows as 2^n — exponentially.

The same explosive growth applies to g^x. With g=2: 2^10 = 1,024. 2^30 = 1,073,741,824. 2^100 ≈ 10^30. The number of possible values of x an attacker must search also grows exponentially — which is exactly what makes brute-force reversal infeasible.

Real World: Compound Interest

A bank account earning 10% per year doubles roughly every 7 years. After 70 years, $1 becomes $1,024. After 700 years it becomes $10^29. The forward calculation — how much do I have after x years? — is trivial. The reverse — how many years did it take to reach this exact balance? — requires logarithms, and with modular arithmetic even logarithms do not help directly.

Modular Exponentiation — the Trapdoor

g^x mod p combines exponential growth with modular wrapping. The wrapping destroys information about how many full cycles occurred, just like the clock. Even though g^x grows enormously, the output is always a small number between 0 and p−1.

Concrete example: 3^7 mod 23. Without mod: 3^7 = 2187. With mod: 2187 mod 23 = 4. Given only g=3, p=23, and result 4, finding x=7 requires trying every candidate — there is no shortcut formula.

This asymmetry — fast forward, no reverse shortcut — is called a trapdoor and is the foundation of Diffie-Hellman key exchange.

Why Large Primes Matter

With p = 12, an attacker can try all 12 possible values of x in milliseconds. With p = 2^2048 (a real cryptographic prime), the number of candidates exceeds the atoms in the observable universe. No computer can brute-force it.

Concept · 04
Hash Function
Three Core Properties

Deterministic — the same input always produces exactly the same output. Hash("hello") is always the same value, everywhere, every time.

Avalanche effect — changing even one character in the input produces a completely different output. "hello" and "hellO" have unrecognisably different hashes.

Fixed output size — no matter how long or short the input is, the output is always the same length. A single character and a 10,000-word document produce hashes of identical size.

How a Simple Hash Works

This lab uses a hand-built hash based on the djb2 algorithm. It maintains a single running state that is updated once per character:

state = (state × 33) XOR charCode

The critical word is running. The state after step 3 is not just a function of character 3 — it is a function of every character before it combined, because it was built up cumulatively. Each step multiplies the entire accumulated history by 33 before mixing in the next character.

This is fundamentally different from a weighted sum like c[0]×p⁰ + c[1]×p¹ + ... where each character contributes independently. In a sum, changing one character affects only its own term. In a running state, changing character 0 produces a different state at step 0, which feeds into step 1, which feeds into step 2 — the difference compounds through every subsequent step. By the last character the change has touched every multiplication, producing an unrecognisably different result.

The constant 33 is not a prime — it is 3 × 11. It is chosen because state × 33 can be computed as (state << 5) + state using fast bit shifts, and it happens to produce good distribution in practice. Real constants are chosen empirically, not theoretically.

Why Not Store Passwords as Plain Text?

If the database is stolen, every password is immediately exposed. With hashes, the attacker gets a list of hash values, not passwords. To recover a password they must find an input that produces the same hash — which is the one-way function problem from Tab 2.

Concept · 05
Web Crypto API
From hand-built to SHA-256

The hash in Tab 4 demonstrates the idea but is trivially breakable. Real applications use SHA-256, a standardised algorithm designed by the NSA and vetted by decades of public cryptanalysis. The output is always 256 bits (64 hex characters).

Why crypto.subtle is async

The browser offloads crypto.subtle operations to native code outside the JavaScript thread. This keeps the UI responsive during expensive operations. The function returns a Promise — you must use await (or .then()) to get the result.

Three operations for Feature 8

Generate salt — crypto.getRandomValues(new Uint8Array(16)) produces 16 cryptographically random bytes. Convert to hex for storage.

Hash with salt — concatenate salt + password, encode to bytes with TextEncoder, pass to crypto.subtle.digest('SHA-256', ...).

Verify — on login, retrieve the stored salt, hash the submitted password with it, compare hex strings. Never compare passwords directly.

What is stored vs what is never stored

Stored in localStorage: displayName, username, salt (plain text), hash (hex string). Never stored: the original password. It exists only in memory for the duration of the function call, then is gone.
